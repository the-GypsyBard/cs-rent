# IGXE 个人租赁账本

Windows 本地采集管理原型。数据保存在本项目 `data/`，界面使用 Edge 独立应用窗口，后台仅监听 `127.0.0.1:17863`。这是本地桌面窗口应用，尚未打包为独立 EXE。

## 启动

双击 **启动应用.cmd**。本机可使用 Codex 自带的 Node.js 和 Playwright，无需先安装依赖。迁移到其他电脑时，需要 Node.js 24+、Microsoft Edge，再双击 **安装依赖.cmd** 安装项目依赖。

1. 进入“采集中心”，点击“打开采集浏览器”。
2. 在独立 Edge 窗口登录 IGXE。当前 Codex 内置浏览器的登录不会自动迁移。
3. 确认登录的是此账本对应的个人账户，勾选账户确认框。
4. 首次选择“全量复核”，点击“开始采集”。采集期间不要手动操作采集窗口。
5. 完成后查看“同步报告”。仅当目录覆盖和详情任务均通过才标记覆盖核对通过。字段警告仍需单独核对。

关闭界面不会停止后台。要完全退出，请点击左下角“退出应用服务”，会等待当前任务暂停并关闭采集会话。

## 已实现

- 两次遍历订单列表，比较订单集合与商品数量；等待内容换页，而非仅等待页码变化。
- 按订单号归档；订单概要和详情分开保存；失败不覆盖已有成功详情。
- 展开租期与金额提示，保存首租、续租、逾期续租、租金和加成。
- 保存磨损字符串、原始字段、不同订单的归还/到期/截止时间及赔付原文。
- 全量、增量、继续未完成详情三种模式；任务持久化；失败退避重试。
- 搜索、状态筛选、详情、原始数据、同步报告、JSON导出、SQLite在线备份。
- 仅操作订单列表分页与详情提示控件，不执行收货、发货或任何交易操作。

## 数据口径与限制

- **订单金额不是已核验实际到账**，押金不计入订单金额合计。首版不采集资金流水，不计算真实净收益。
- 原始页面未提供的字段不推算。百分比标记不自行解释为特定饰品属性。
- 一套 `data/` 只绑定一个账户。会检查显示昵称，但掩码昵称不能可靠唯一标识账户，因此还需要用户确认。多账户使用不同项目副本或分别设置 `IGXE_DATA_DIR`。
- 浏览器登录状态保存在 `data/browser-profile/`。请勿分享该目录；JSON导出不含浏览器登录信息。
- “总商品数量”不是订单数。按实际商品行核对，若平台改为其他数量口径会标记覆盖未通过。
- 页面可变化，选择器需维护。没有使用未经验证的内部接口，也没有保证无人值守登录或绕过验证。
- 当前零订单账户会停止并提示人工核验，而不会视为空数据同步成功。
- 续采详情不会重新检查目录；再次全量/增量同步才能得到新的覆盖结论。目录阶段中断会重新扫描，详情阶段已成功任务不会丢失。
- 增量模式仍核对全目录，只对新单、变化、非完成、失败、缺详情或超过7天未刷新的订单读详情；需要强制刷新所有终态订单时用全量。
- 已完成同步是页面采集的一致性结论，不是平台数据库完整性证明。缺失历史订单只提示，不自动删除本地数据。

## 文件

- `src/collector.mjs`：采集、分页、等待条件、重试与任务调度。
- `src/parser.mjs`：字段解析及金额/租期校验。
- `src/store.mjs`：SQLite、任务、快照和备份。
- `src/server.mjs`：本地接口和访问校验。
- `public/`：中文管理界面。
- `tests/`：基于已观察样本的解析、异常保护、幂等和恢复测试。

数据库：`data/orders.sqlite`；启动日志：`data/server.log`、`data/server-error.log`。备份按钮生成 `data/backup-时间戳.sqlite`。恢复时先退出服务，将当前整个数据目录另行备份，再用选定备份替换 `orders.sqlite`，同时移走旧的 `orders.sqlite-wal` 和 `orders.sqlite-shm`；保留浏览器会话前请确认对应同一账户。

## 开发与验证

```powershell
node --test --test-isolation=none tests/*.test.mjs
node src/server.mjs
```

可配置环境变量：`PORT`（默认17863）、`IGXE_DATA_DIR`（默认项目内data）、`IGXE_BROWSER_CHANNEL`（默认msedge）。双击启动器固定连接17863。

研究依据为2026-09-16已登录页面抽样：订单7806653、3581353、8120772及首页/第二页/末页。单元测试不等于独立采集浏览器已全量实测。首次真实全量采集须在独立浏览器完成登录后进行，并检查报告。
